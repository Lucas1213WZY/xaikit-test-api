# Consolidated human study data

Every table here is generated by `assets/build_human_data.py` from read-only
sources. Do not edit these files by hand — rerun the script instead:

```bash
python assets/build_human_data.py          # rebuild
python assets/build_human_data.py --check  # verify against sources
```

## Anonymisation

Participants are renumbered `1..N` **per study**, so CoAX participant 1 and
CoXAM participant 1 are different people. Numbers are assigned by sorting the
raw identifiers lexicographically, which is deterministic and does not leak the
order people took part in. The identifier column keeps its original name and
position, so existing loaders keep working.

No Prolific ID, study ID or session ID survives into these tables. For sim2real
the `code`, `prolific_id`, `study_id` and `session_id` columns are dropped
outright.

The sim2real participant key is **`prolific_id`, not the `clinical_<code>` file
name** — the files count *sittings*, not people. Two people sat the study twice
under different codes, and in both cases under a *different* `explanation_type`,
so keying on the file name would have counted them as four participants in
conditions they shared. `participant_session` numbers a person's sittings.

`participant_id_map.csv` is the **re-identification key** — the one file here
that must never be shared. `assets/human_data/` is gitignored in full.

### Notes per study

**CoAX** — the trial log covers four datasets, but the refit covers only
`adult`, `forest_cover` and `wine_quality`; `mushrooms` was collected and never
fitted. `appId` is renamed to `dataId` throughout, matching the public spelling.

**CoXAM** — 80 rows carry no participant ID in the source and keep a blank one
here.

The five fit tables are CoXAM's **published** fits, produced by the study's own
notebooks: a DDM-with-timing model (`T_enc`, `ddm_a`, `ddm_s`, `lapse`,
`retrieval_threshold`, …) fitted by GP optimisation jointly on response NLL and
time MAE. They are *not* the RL meta-policy parameters that
`fit_coxam_to_participants.py` searches — different model families, not
interchangeable. Use these for anything the paper reports.

Coverage is uneven, and the gap is in the export rather than in the fitting:

| task | dataset | participants | per-trial predictions |
|---|---|---|---|
| forward | mushrooms | 137 | yes — `p_resp`, `Model Prediction`, `NLL` |
| forward | wine_quality | 90 | **no** — fitted parameters and `respNLL` only |
| counterfactual | both | 270 | yes — `coxam_counterfactual_replay.csv` |

`coxam_counterfactual_replay.csv` is the counterfactual **replay** and supersedes
`coxam_counterfactual_fit.csv`, whose 50 participants are a subset of its 270. It
is built from an `.xlsx` the study exported from JMP, so the build needs
`openpyxl`, and one all-blank export artifact row — whose `Participant Id` field
holds the string `Changed AI prediction` — is dropped via `drop_blank_rows`.

Its own vocabulary differs from the other tables: conditions are spelled
`Decision Tree` / `Linear Regression` / `Hybrid` and datasets `Mushrooms` /
`Wine Quality`. Values are left exactly as exported; the plot builder maps them.

The measures pair human against model twice over, and they are **not**
interchangeable:

| measure | human column | model column |
|---|---|---|
| edit flipped the **AI** | `Changed AI prediction` | `Model changed AI prediction` |
| edit flipped the **explainer** | `Changed explainer` | `Model changed XAI prediction` |

The report uses the **AI** pair only.

So wine_quality forward *is* fitted; it simply never had a per-trial dump
written. Reproducing one needs a single run per participant using the saved
parameters — no search.

Deliberately not consolidated: `cf_attempts_all_methods.csv` and
`forward_simulation_wine_quality_v_0.2.csv`, which look like fits but are pure
model simulations. Their participant IDs (`LR_CALC-P1`, `1`, `10`, …) have zero
overlap with real participants, and the former's `Changed AI` column is entirely
null.

**sim2real** — combined from the 95 per-sitting files, **screened down to 46**.
Screening reuses the fitter's own rule via `load_screened_participant_trials`
(exactly one response for every expected test qid, plus a valid
`explanation_type`), so this table and the fits agree on who counts by
construction rather than by a re-implemented rule. All 49 exclusions are
`incomplete_or_invalid_test_qids`, and they are exactly the files written
against the older schema that lacks `question_type`.

`sim2real_screening.csv` records every sitting's outcome. Excluded rows carry a
blank `participant_id`, since only eligible sittings are numbered.

The 46 kept sittings all share the richer schema, so `participant_session` is
currently 1 throughout — it exists so that loosening the screening rule cannot
silently merge one person's two sittings into a single participant.

`responses` holds self-reported demographics and `strategy` holds free text,
both as collected.

`sim2real_fit_predictions.csv` and `sim2real_participant_fits.csv` are the four
per-condition fit outputs from `server_runs/sim2real_refit_strategies`,
concatenated and **renumbered onto these participants**. The fitter keyed on the
raw `clinical_<code>` session code, so anything reading `server_runs/` directly
is reading un-anonymised identifiers — read these instead. This is the source
behind the sim2real panels of the comparison report.

## Superseded

`CoAX/coax-3-datasets-user-responses.csv` and
`CoXAM/coxam-mushrooms-wine-quality-user-responses.csv` predate this script and
**still carry raw Prolific IDs**. They are byte-identical to their sources apart
from the `appId`→`dataId` rename, and are fully replaced by
`coax_human_trials.csv` and `coxam_human_trials.csv`. Delete them once nothing
reads them.
